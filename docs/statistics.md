# 统计口径说明

这份文档把报告里每一个数字的**定义、分母、计算方式**写清楚。评审里最容易出问题的不是公式，而是分母。

---

## 1. 时间对齐

### 1.1 时间表示

| 来源 | 时间字段 | 是否有日期 | 内部表示 |
|---|---|---|---|
| NMEA GGA | `hhmmss.ss` | 否 | 当天秒 `0..86400` |
| RTKLIB POS/STAT | `yyyy/mm/dd hh:mm:ss.ss` | 是 | UNIX 绝对秒 |
| UTC 表格 | `UTCDate` + `UTC` | 视文件而定 | 绝对秒或当天秒 |

`EpochSeries.hasDate` 标记整份文件的口径；解析器遇到混用（部分行缺日期）会统一退化为当天秒并写警告。

### 1.2 跨零点

无日期文件先在**文件顺序**上展开：

```
raw:  86399.0 → 0.5 → 1.5
展开: 86399.0 → 86400.5 → 86401.5
```

顺序很重要：先按数值排序会把 `00:00:01` 排到 `23:59:59` 前面，整段轨迹被拆散。展开之后再排序才是安全的。

### 1.3 两侧口径不同

一侧有日期、另一侧只有时刻时，以**有日期一侧的首个历元**为参照，把时刻补成绝对时间：

```
offset = floor((refStart - todStart + 43200) / 86400) * 86400
```

即"取与参照时刻最近的那一天"。报告"时间对齐"一节会打印 `differentTimeBases=true` 与补全说明。

### 1.4 匹配

- 双指针线性扫描，两侧按时间递增；
- 匹配容差默认 `±0.1 s`（`--tolerance` 可调）；
- 一个基准历元最多匹配一个评估历元；
- 匹配率过低（<50%）会写入警告。

## 2. 误差定义

以基准文件首个历元的 BLH 为原点建立 ENU：

```
planeError  = sqrt(ΔE² + ΔN²)      // 平面误差（m）
heightError = |ΔU|                 // 高程误差（m）
```

不用"经纬度差换算成米"，也不直接用椭球高之差——ENU 的 Up 分量已经包含了参考点处的法线方向修正。

---

## 3. 样本分类

| 报告中的类别 | 基准解状态 | 评估解状态 | 用途 |
|---|---|---|---|
| 固定解-固定解 | Fix | Fix | 主精度指标、连续可用性 |
| 固定解-浮点解 | Fix | Float | 浮点解精度参考 |
| 基准固定解-全部评估点 | Fix | 任意 | "全部数据"口径的误差分布 |
| 基准浮点解 | Float | 任意 | 浮点解基准下的对比 |

解状态码沿用 RTKLIB：`0=无效 1=固定 2=浮点 3=SBAS 4=DGPS 5=单点 6=PPP`。GGA 的 `quality` 由 `normalizeNmeaQuality()` 翻译（4→1、5→2、2→4、1→5、6→6）。

---

## 4. 误差分布的分母

**分母 = 基准固定解匹配历元数**（`matchedBaselineFix`），不是全部匹配历元。

这是旧版本的真实 bug：

```
旧：占比 = 满足阈值的点数 / compareTotalCount   // 全部匹配点
新：占比 = 满足阈值的点数 / matchedBaselineFix  // 只用基准固定解样本
```

举例：基准 10 个固定解 + 10 个浮点解，评估全为固定解且误差均 0.1 m。

- 正确：`<1 m` 占比 = 10 / 10 = **100%**
- 旧版：10 / 20 = **50%** —— 基准里的浮点解把固定解精度的占比稀释了一半。

报告第五节、HTML 的误差分布表都会显式打印分母，避免读者误解。

---

## 5. 精度指标

设样本 $x_1..x_n$：

| 指标 | 公式 | 说明 |
|---|---|---|
| 均值 | $\bar{x} = \frac{1}{n}\sum x_i$ | 系统性偏差方向 |
| RMS | $\sqrt{\frac{1}{n}\sum x_i^2}$ | 含偏差的均方根，GNSS 报告常用 |
| 标准差 σ | $\sqrt{\frac{1}{n}\sum (x_i-\bar{x})^2}$ | **总体**标准差（不是样本无偏估计） |
| CEP50 | 50% 分位 | 中位数误差 |
| 95% | 95% 分位 | 不是 $1.96\sigma$，是经验分位 |
| P68/P95/P99 | 68.27%/95.45%/99.73% 分位 | 旧版误称 1σ/2σ/3σ |

分位数采用线性插值：位置 $p(n-1)$，取相邻两点插值。

**σ 与 P68 不是一回事**：只有零均值高斯分布下二者才近似相等。轨道/多路径误差分布通常有偏、有厚尾，所以报告并列给出两者——想用哪个由读者判断，工具不替读者下结论。

## 6. 连续可用性

```
分子 = 匹配点中「基准 Fix 且评估 Fix 且 planeError < 0.05 m 且 heightError < 0.08 m」的历元数
分母 = 评估文件总历元数
```

注意分母是**评估侧总历元**（含未匹配上的），因此它衡量的是"整段观测里有多少时间满足厘米级可用"，而不是"匹配上的人里有多少合格"。

---

## 7. 初始化时间

```
t_init = 评估文件首个固定解历元时间 - 评估文件首个历元时间
```

- 若评估文件第一个历元就是固定解，`t_init = 0`；
- 若整个评估文件没有固定解，记为 `N/A`（内部值 `-1`）；
- 使用展开后的连续时间，跨零点不会出现负值。

---

## 8. 完整率与固定率（文件级）

- 采样间隔：相邻历元时间差的**中位数**（对丢包/断点不敏感）；
- 应有历元数：`round(span / interval) + 1`；
- 完整率：`实际历元 / 应有历元`，上限 100%；
- 固定率：`解状态 = Fix 的历元 / 总历元`。

旧实现的完整率恒为 `100%`，等于没有这个指标。

---

## 9. 未做的事（明确写出来）

- 不做 GPST↔UTC 转换：时间以文件记录为准。两侧基准不同会出现 18 s 偏差，报告会以"匹配率过低"提示，而不是静默修正。
- 不做粗差剔除：误差分布按全样本统计，`maxPlane/maxHeight` 会如实暴露野值。
- 不做速度精度：数据源无速度列。
